# Wave 5: purse, Labours, Gloria, Focus with real guards, tab motion, palettes (31 Oct 2026)

The developer's second list from 31 Oct, planned. It joins 1.1.0 (nothing has shipped), logged in [releases/v1.1.0.md](releases/v1.1.0.md). Status is kept in the table at the end.

## 0. Build order and ownership

The list touches Today, the ledger and the guard bridge from several sides, so it is built in three phases. Each step owns its files; shared files (copy index, `stores/index.ts`, `db/index.ts`) are edited in place, never rewritten.

| Phase | Step | Owns                                                                                                           |
| ----- | ---- | -------------------------------------------------------------------------------------------------------------- |
| 1     | A    | Fixes and palettes: reset and loss notice, free training without day context, calendar, order charts, palettes |
| 1     | B    | Native focus guards: `modules/vigil` (Kotlin) and the `guardBridge` contract in section 7                      |
| 1     | C    | Tab motion: directional slide, swipe between tabs, a return animation on each tab                              |
| 2     | D    | Economy: the purse counter, coin flight, Labours, claimable Decorations, Gloria, the day detail sheet          |
| 2     | E    | Focus: the Focus tile, setup screen, Comites, slide to begin, the active screen and screensaver, sounds, log   |
| 3     | F    | Integration, review, edge cases, docs, HISTORY, release log                                                    |

Migrations: D owns `0012`. E adds none (truces and focus rows already carry what it needs; a new column waits for F).

## 1. Fixes (step A)

1. **Reset shows the loss screen.** After "Reset the journey" the notices are cleared before the live queries catch up, so `useLossNotice` sees the old break as new and opens `/campaign-lost`. Fix:
   - The loss notice runs only with a loaded active arc of kind `campaign`, and only for a break on or after that arc's start day.
   - The campaign-lost screen leaves (to `/`) when there is no campaign to show.
   - Reset sends the user straight to the first onboarding screen (the onboarding store is cleared first).
2. **Free training has no day context.** No "DAY XII OF LX", no Truce banner, no loss screen, no sick-day Truce. The hero shows the run (days in a row) when there is one, otherwise just today. All campaign wording waits for a campaign.
3. **Calendar (Vidi):** move back month by month to the first month with a record (or the arc's start), forward to this month; days with no activity show empty, never hidden.
4. **Order charts (Vidi):** only the user's own orders get a chart. Vinco's four already have theirs.

## 2. Palettes (step A)

- **Nox** becomes the default dark palette. A saved choice is kept; only the default changes.
- A new light palette, **Alba** ("first light"), designed for the new hero, tiles and glows.
- **Light fit pass:** every light palette (Marble, Papyrus, Calx, Alba) checked on Today's hero, tiles, the focus screens, sheets and cards. Glows are softer on light (they read as a stain at dark strength), hairlines a step stronger, shadows soft. Contrast tests run on every palette.

## 3. Tab motion (step C)

- **Directional slide:** moving right (Veni to Vidi) slides the new tab in from the right, moving left slides from the left, on a spring. Reduce motion: a plain cross-fade.
- **Swipe:** a horizontal swipe on a tab's content moves to the next or previous tab. It never fights vertical scroll, horizontal lists or sheets (it starts only past a clear horizontal threshold).
- **Coming back to a tab** replays one small motion:
  - **Veni:** the day path draws to now and the order notches pop in, in time order.
  - **Vidi:** the stat numbers roll and the week bars rise.
  - **Vici:** the rank bar fills to the current rank.
- Check the Expo Router 57 docs for the tabs `animation` option and the vendored React Navigation version before choosing the mechanism.

## 4. Purse, coin flight, Labours, Decorations (step D)

As built: [REWARDS.md](REWARDS.md) (HUD, reward flight, Labours, Decorations, Gloria, claims data).

**The purse counter (HUD):**

- A small pill at the top right of each tab (beside the user button on Veni): a coin and the denarii count. It replaces the big purse tile.
- Tapping it opens the Forum.
- **Elastic count:** when the total changes, the number counts to the new value with a spring that overshoots slightly, and the coin pulses.

**Coin flight:**

- A layer above the tabs. A claim launches a few coins from the claim button.
- They burst out, then arc to the purse pill. Each landing ticks the counter and plays a light haptic.
- The ledger row is written first. The flight is only the show, so a killed app never loses or doubles pay.
- Reduce motion: no flight; the counter changes once.

**Labours (Labores, "tasks to earn"):** a bounty board that replaces the Forum's flat "ways to earn" list.

- **Daily** (new every day) and **Weekly** (Monday to Sunday) labours, each with a goal, live progress and a reward in denarii and Gloria.
- Examples:
  - **Daily:**
    - Take today's selfie.
    - Log your weight.
    - Focus 25 minutes.
    - Finish 3 to-dos.
    - Conquer the day.
  - **Weekly:**
    - Hold 5 days.
    - Conquer 3 days.
    - Focus 3 hours.
    - Wake on time 5 days.
- **When it's done, it waits to be claimed.** A claim pays once per period (stored, unique). An unclaimed labour expires with its period.
- **Today shows the top 3:** claimable first, then the closest to done. "See all" opens `/labours`, grouped by type, with what each pays and when it resets.
- Automatic pay stays automatic: the held or conquered day and run pay (Stipendium) are wages, not bounties, and keep their live-pay and undo rules.

**Decorations become achievements (Vici):**

- Every decoration is listed: earned ones with a "Claim" button and their reward until claimed, locked ones with their rule and progress.
- Claims pay once, forever.

**Gloria (XP).** The plain label is "glory points".

- **Derived from the records,** so an undo takes it back:
  - An order at its minimum: +10.
  - An order at its full goal: +5 more.
  - A conquered day: +20.
  - A to-do done: +3.
  - A focus held to the end: +1 for each minute.
  - Labour and decoration claims: +their stated Gloria (stored with the claim).
- **Vidi:**
  - A Gloria section: the total, this week by day.
  - The calendar tints each day by its Gloria.
- **Tapping a calendar day** opens a designed detail sheet, not a list of text:
  - Orders as small rings.
  - Focus minutes, with each session.
  - To-dos done.
  - Gloria and denarii for that day.
  - The selfie thumbnail.
  - Empty days say so plainly.

Data: migration `0012`, a `claims` table (kind `labour` or `decoration`, key, period, denarii, gloria, claimed_at, unique on kind, key and period). Claimed denarii go to the ledger as a claim row; step D checks the ledger's unique keys so two claims on one day never collide.

## 5. Focus (step E)

**Entry:**

- On Veni, the second tile is now Focus: it shows "Ready", or the time left while a focus runs.
- Tapping it opens `/focus` with a spring.
- The old Focus row and the morph overlay go.

**Setup screen, top to bottom:**

1. **Time.** A big `h:mm` readout.
   - **The ruler:** 5-minute steps, from 5 minutes to 3 hours. The readout always shows the value the ruler sits on, during and after a drag or fling (this fixes the stuck value).
   - **Presets:** 15m, 25m, 45m, 1h, 1h 30m, 2h.
   - **Custom:** hours and minutes typed in, any whole minute from 5 to 180.
2. **Guard.** Three cards in a row, each with its avatar (Level I, II, III). The selected card shows its rules below the row.
   - **Custos (Level I, "Watch")**
     - Opening any app outside the Comites shows an alert.
     - A small floating timer stays on screen.
     - Every 3 minutes in such an app, a "back to the line" popup.
   - **Imperium (Level II, "Limit")**
     - Opening an app outside the Comites shows an overlay and starts a 3-minute timer.
     - At 3 minutes Vinco closes the app and returns to the focus screen. That app can't be opened again for 3 minutes.
   - **Silentium (Level III, "Lockdown")**
     - Only Vinco, the Comites and the Phone app.
     - No home screen, no notification shade, no recent apps.
     - In Vinco, Back and the back gesture can't leave the focus screen.
3. **Comites ("your three companions").** Up to 3 apps allowed during every guard.
   - The Phone app is always allowed and always shown.
   - Empty slots show "+". The picker lists the phone's launchable apps (native).
   - Saved on the phone (guard store).
4. **Reward line:** what holding to the end pays (denarii and Gloria).
5. **Slide to begin.** A track with a knob, not a tap. If the user holds no Truce, a small sheet appears:
   - Title: "No Truce".
   - Body: retreating early will cost 50 denarii, or a 30-second stand-down if the purse is short.
   - Buttons: "Get a Truce" (the Forum) and "Begin anyway".

**The active screen** (clean, bold, no filler):

- The time left as a large `h:mm` with the seconds beside it.
- An "Ends at 4:30 pm" tile.
- Two tiles:
  - Truces held.
  - A small rain field: pixels falling, decorative, paused when hidden.
- **Slide to retreat.**
  - It spends a Truce.
  - With no Truce, it costs 50 denarii (bought on the spot, like a Truce at need).
  - With neither, the slide starts a 30-second stand-down that the user can cancel.
  - Retreating never pays.
- **The dock:** the Comites and the Phone app, launched from here.
  - With no Comites, it shows the Phone and a "+".
  - The "+" explains that apps are added before a focus starts.

**Screensaver:**

- After 10 seconds without a touch the controls fade.
- The timer drifts slowly around the screen (no burn-in).
- The screen dims to low brightness and is kept awake.
- A tap brings everything back at normal brightness. Leaving the screen always restores the brightness.

**Sounds:** new cues for the session start, the end (held), a retreat and the stand-down tick, made in `scripts/generate-sounds.mjs`.

**Focus log:** on the Focus screen, the total minutes held (today, this week, all time) and the sessions list, each with its day, time, guard, minutes and result.

**Avatars:** three vector emblems, drawn in code from palette roles so they follow every palette.

- **Custos:** an open helmet with a watchful eye slit.
- **Imperium:** a crested centurion helmet.
- **Silentium:** a closed helm.

Illustrated versions can replace them later (the prompts are in HISTORY).

**Why the retreat always has a way out:** a focus can run for three hours, and a phone must never become a trap. Calls are always allowed, and a retreat always exists, at a real cost.

## 7. Native guards (step B): `modules/vigil`

The `guardBridge` contract (`src/features/guard/bridge.ts`) grows to:

- `isSupported`: false in Expo Go and older builds.
- `getPermissions()`: accessibility (the guard service) and overlay (draw over other apps).
- `openPermissionSettings(permission)`.
- `listLaunchableApps()`: package, label, icon (a small PNG data URI). Uses a `<queries>` launcher intent, not `QUERY_ALL_PACKAGES`.
- `getDialerPackage()`: the phone's default Phone app.
- `startFocus({ guard, startedAt, endsAt, allowedPackages })`: the allowed list already holds the Comites, the dialer and Vinco.
- `endFocus()`.
- `onFocusEvent(listener)`: events `nudge`, `appBlocked`, `appClosed`.
- The reel-counting members stay as they are.

**How it works (Android):**

- **An AccessibilityService** watches which app is in front (window state changes).
- **An overlay** (`TYPE_APPLICATION_OVERLAY`) draws:
  - The floating timer (Custos).
  - The alert, and the countdown that closes an app (Imperium).
- **Silentium** brings Vinco back to the front whenever the home screen, recents or another app takes it. It closes the notification shade with `GLOBAL_ACTION_DISMISS_NOTIFICATION_SHADE` (Android 12+), else Back.
- **The session lives in SharedPreferences,** so it survives Vinco being closed or the phone restarting.
- **Hard stops at `endsAt` in native code,** so a dead JS side can never extend it. `endFocus` clears it at once.
- **Always allowed:** the dialer, emergency calls, and Vinco itself.
- **Play policy:**
  - Accessibility used for focus blocking needs the Play declaration and a clear in-app disclosure before the permission is asked.
  - The disclosure screen is part of step E. The declaration is a release task.

## 7b. Added later on 31 Oct

**Reward flight (step D):**

- The header counter is three counters: denarii, Gloria and Truces held.
- A claim shows its rewards on screen first. Then each slingshots to its own counter, which ticks with an elastic overshoot.
- Rewards can include a Truce. At the cap of 3, it converts to its price in denarii, and the screen says so.

**In-app notices (step G, after D and E):**

- One minimal, consistent notice system replaces the current toasts.
- **A queue:**
  - One notice at a time.
  - Duplicates merge.
  - Priority for errors.
- **Each notice** is a quiet pill at the top under the status bar, with an icon, one line and an optional action.
  - Kinds: success, reward, info, warning, error.
  - It springs in and swipes up to dismiss.
  - Errors stay until dismissed or acted on; others last a few seconds.
- **Access:** it is announced to screen readers, and reduce motion makes it fade.
- **One API:** `notify({ kind, message, action? })`, from anywhere.
- Every current Toast use moves to it, and the old Toast goes.
