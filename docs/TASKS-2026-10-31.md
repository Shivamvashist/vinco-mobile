# Wave 4: the real Android build, Aurora, rewards, themes (31 Oct 2026)

The developer's list from 31 Oct, planned. Logged in [releases/v1.1.0.md](releases/v1.1.0.md) (still in progress: nothing has shipped, so Wave 4 joins it). Status is kept in the table at the end.

## 1. A development build that runs everything (native code)

- **Why:** Expo Go can't run custom native code. Aurora (and later the Vigil) need it.
- **What:** `expo-dev-client` plus an `eas.json` `development` profile (APK, dev client), and a `preview` APK that has the same native code but no packager. Commands in [GUARDIANS.md](GUARDIANS.md) and the README.
- After the first install, `npx expo start` sends JavaScript to the dev build like Expo Go. Rebuild only when native code or `app.json` changes.

## 2. Aurora, the alarm (native module `modules/aurora`)

- Local Expo module in Kotlin, implementing `AuroraBridge` (`src/features/aurora/bridge.ts`):
  - **Exact alarm:** `AlarmManager.setAlarmClock`.
  - **Lock-screen screen:** a full-screen intent over the lock screen.
  - **Alarm sound:** looping on the alarm stream.
  - **Reboot:** reschedules on `BOOT_COMPLETED`.
  - **Exact-alarm permission:** checks it and opens its settings page.
- **Ring screen** (`/alarm`): full-screen and always dark. It stops only through a mission, "I'm sick" (sick-day Truce), or an alarm pass.
- **First mission: march** (30 steps, `expo-sensors` Pedometer, with a tap-counting fallback when no step sensor is present).
- **Beating it first try:**
  - 2 denarii (ledger reason `aurora_first_try`).
  - Wake-up is logged.
- Expo Go keeps the stub: the screen still says "Arrives with the Vinco build".

## 3. Notifications

**Default (local, on the phone):**

- The full plan is in [NOTIFICATIONS.md](NOTIFICATIONS.md): morning orders, evening "seal the day", last call, the Truce window, and streak rewards ahead.
- **Rules:**
  - At most 3 nudges a day, plus the alarm.
  - Written for all three tones.
  - Planned 3 days ahead and rewritten whenever the day changes.
  - A reminder whose job is done is withdrawn.
- **Settings:** Reminders in Settings (on or off for each kind, evening time).

**From the admin panel (later):**

- Push through Expo's push service.
- **Backend base, built now in `vinco-backend`:**
  - Push tokens per install.
  - Notifications composed in admin, with an audience preview.
  - A dispatch job and a receipts job.
  - Admin endpoints, plus a frequency guard.
- **App side:** the token is fetched and stored now; it is sent once the app is wired to the API (backend Phase 4).
- **Not built yet:**
  - The admin panel itself (its own repo).
  - FCM credentials (Firebase project, `google-services.json`, uploaded to EAS): the developer's account step.

## 4. Theme control: palettes for dark and light

- A **theme** stays fonts and sounds (Vinco). A **palette** is one full set of colour roles, dark or light.
- **The user picks:**
  - A mode: dark, light or system.
  - A dark palette.
  - A light palette.
  - In system mode the phone switches between the two picks.
- **Palettes:**
  - **Dark:** Basalt (default), Nox (true black), Purpura (imperial purple), Aes (bronze green).
  - **Light:** Marble (default), Papyrus (parchment), Calx (limestone).
  - Every palette passes the same contrast tests as Basalt and Marble.
- **Appearance screen** (`/appearance`, from Settings): the mode, then each palette as a live mini preview (a row, a button, a chip) drawn in its own colours. Applies at once.
- **Saved:** `darkPaletteId` and `lightPaletteId` in preferences, checked on restore: an unknown id falls back to the default.
- **Unchanged:** day card styles stay separate, so a shared card looks the same everywhere.

## 5. Orders on Today

- **Orders with levels** (water, meals, own counted orders): a minus and a plus on the right of the row. Tapping the row still adds one; the minus replaces the long press, which also still works.
- **Done-or-not orders:** the check circle toggles (tap to do, tap to undo). Long press still undoes.

## 6. Charts for orders (on or off)

- Vidi's Commentarii shows a week chart for each order: water, workout, and own counted orders.
- Each chart can be hidden or shown (`hiddenOrderCharts` in preferences; own orders by id).
- Done-or-not orders show a week of ticks instead of bars.

## 7. Denarii when the day holds, and the streak

- **Live pay:**
  - The moment today holds (or is conquered), its denarii are paid: 5 held, 10 conquered.
  - Undoing an order so the day no longer holds takes them back. The same goes for conquered dropping to held.
  - Sealing at midnight makes the day's award final (it replaces the live one, never adds to it).
- **Streak rewards (the Stipendium):**
  - Paid on a run of held days, in both campaign and free training.
  - Days 3, 5 and 7 of each week of the run pay extra denarii (10, 15, 25).
  - **Campaign only:** every 7th day grants a Truce. Truces stay campaign only.
  - Milestones at 14, 30, 60 and 100 days pay a bonus.
  - Streak denarii are live too and come back off if today stops holding.
  - Truces are granted at the midnight seal only, so a Truce is never taken back after it was spent.
- **On Today:** a small streak card shows the run and the next reward ("2 days to a Truce").
- **Change to the rules:** free training now earns streak denarii (it had no weekly bonus). It still has no Truces and no loss.
